Binary Search Trees (BST)

A BST organizes data so that every node's left subtree contains smaller values and its right subtree contains larger values. This allows O(log n) search, insert, and delete — without hashing.

💡 Key Idea: BST inorder traversal always gives SORTED output. Insert a random permutation of numbers, traverse inorder — they come out sorted. This is the basis of treesort and understanding how databases maintain sorted indexes.

🌍 Real-World Applications

🗄️
Database Indexes (B-Tree)
MySQL and PostgreSQL use B-Trees (a generalized BST) for table indexes. When you query WHERE id = 12345, the database traverses the B-Tree in O(log n) instead of scanning every row.
🔧 BST-based O(log n) index lookup
📝
Autocomplete / Spell Check
Spell checkers store dictionaries in BSTs or Tries. Typing 'rec' traverses right to 'recursion', 'rectangle', etc. Each character narrows the tree by O(log n) per step.
🔧 BST for ordered word lookup
📊
Financial Trading Systems
Stock exchanges maintain order books (buy/sell orders) in BSTs sorted by price. Matching the best bid and offer requires finding the min/max — O(log n) with BST vs O(n) linear scan.
🔧 BST for real-time order matching
🎮
Game Collision Detection
Games use BSP (Binary Space Partitioning) trees to organize the game world. Rendering and collision checks only examine objects near the camera — pruning irrelevant branches in O(log n).
🔧 Spatial BST for efficient collision queries
